## 一、产品概述

### 1.1 产品定位
DJAgent是面向物流/供应链场景的智能风险管控数字员工，通过AI Agent（Claude SDK）协助业务负责人和一线人员完成风险数据分析、任务分派、和反馈管理工作。核心目标是实现风险识别自动化、任务分配智能化、反馈审核高效化。

### 1.2 核心价值主张
| 指标 | 目标值 |
|------|--------|
| 风险识别效率提升 | 80% |
| 人工核查成本降低 | 60% |
| 任务完成时间减少 | 60% |
| 风险识别准确率 | 90% |

### 1.3 目标用户与角色
- **业务负责人** (Manager): 风控部负责人、普通分析人员 - 使用Manager Agent进行数据分析、任务创建、智能决策
- **一线人员** (Staff): 快递员、仓管员、质检员等操作人员 - 使用Staff Agent接收任务、上传反馈材料、获得核查指导

### 1.4 用户权限模型
| 角色 | 风险数据权限 | 任务权限 | 所属地区 |
|------|-------------|---------|--------|
| 总部管理员(EMP_000) | 所有地区 | 所有任务 | 总部 |
| 业务负责人/分析人员 | 所属地区 | 自己创建的任务 | 总部/区域 |
| 一线人员 | 所属地区 | 分配给自己的任务 | 总部/区域 |

## 二、核心架构设计

### 2.1 系统三层架构

```
┌─────────────────────────────────────────┐
│         Frontend Layer (React)            │
│  LoginPage / ManagerWorkspace /          │
│  StaffWorkspace + WebSocket/SSE          │
└────────────────┬────────────────────────┘
                 │
        HTTP/REST API (FastAPI)
                 │
                 ▼
┌─────────────────────────────────────────┐
│      Agent Layer (Claude Agent SDK)      │
│  UnifiedAgent → ManagerAgent/StaffAgent  │
│  SessionManager (per user_id cache)      │
│  MCP Server (tool registration)          │
└────────────────┬────────────────────────┘
                 │
        Tool/Skill Execution
                 │
                 ▼
┌─────────────────────────────────────────┐
│    Data Access Layer (File-based)        │
│  CSV (users, tasks, risk_data)           │
│  JSON (feedback, chat_history)           │
└─────────────────────────────────────────┘
```

### 2.2 核心设计原则

#### 2.2.1 配置驱动的Agent模式
- UnifiedAgent根据AgentConfig实例化Manager/Staff模式
- 动态工具权限控制（allowed_tools列表）
- 完全委托Claude SDK处理ReAct循环和自主规划

#### 2.2.2 动态Skill注册和执行
- 自动扫描skills/目录，零配置注册
- SkillOrchestrator通过关键词匹配自动选择Skill
- 支持即插即用，无需修改核心代码

#### 2.2.3 会话管理和缓存策略
- SessionManager按user_id维护Agent会话缓存
- 每个用户独立的Agent实例，避免状态污染
- 支持多用户并发访问

#### 2.2.4 文件驱动的数据存储
- users.csv: 用户信息和权限
- tasks.csv: 任务元数据和状态
- risk_data_*.csv: 日度/月度风险数据
- feedback/{task_id}.json: 聊天历史和反馈内容

## 三、核心功能需求

### 3.1 用户管理

#### 功能要求
- **用户登录**: 多用户选择，支持Manager/Staff两种角色
- **用户切换**: 不刷新页面快速切换身份（顶部个人中心）
- **权限控制**: 根据角色显示不同工作区和数据权限

#### 工号系统说明
所有用户使用`employee_id`（如EMP_001）作为唯一标识：
- 任务创建/查询统一使用employee_id
- SSE推送使用employee_id
- 前端API调用统一使用employee_id

| 字段 | 说明 | 示例 |
|------|------|------|
| user_id | 旧版兼容字段 | 001, 002 |
| employee_id | 工号（推荐） | EMP_001, EMP_002 |
| region | 所属地区 | 总部/上海区/北京区 |
| role | 用户角色 | 业务负责人/一线人员 |

### 3.2 风险数据管理

#### 功能要求（业务负责人专属）

**数据视图**:
- **日度Tab**: 查看每日风险明细（从risk_data_*.csv加载）
- **月度Tab**: 查看月度汇总数据（从risk_data_monthly_*.csv加载）

**风险数据列表功能**:
- 表格展示，支持分页（5/10/20/50/100条/页）
- 支持全选/多选，支持按列排序
- 风险等级可视化（高/中/低三色标记）
- 全局搜索：检索风险明细和任务
- 地区筛选：根据用户region自动过滤数据
- 字段筛选：按指定字段精确搜索

**风险统计看板**:
- 高风险数量统计
- 中风险数量统计
- 低风险数量统计

**数据字段**（共23个字段）:
- 运输信息: 运单号、发货地、收货地、发货网点、收货网点
- 人员信息: 揽收人、揽收人ID、对账人
- 物品信息: 货物类型、产品类型、重量、体积
- 费用信息: 运费金额、结算金额
- 时间信息: 发货时间、揽收时间、派件时间、签收时间
- 状态信息: 运单状态、**异常类型**（超时派送/虚假签收/重量异常等）、**风险等级**（高/中/低）
- 权限信息: region（地区字段）

### 3.3 任务管理

#### 任务列表（业务负责人）
- 显示所有创建的任务
- 按状态筛选：已创建/已下发/已完成/已超时
- 按任务类型筛选：日度/月度
- 显示信息：任务ID、风险简述、状态、执行人、创建时间
- 任务区域可折叠

#### 任务详情
- 完整任务信息（创建人、执行人、截止时间等）
- AI生成的反馈总结
- 上传文件列表（含下载链接）
- 完整聊天历史

#### 任务创建流程
1. 业务负责人通过对话触发Manager Agent的task_creator Skill
2. Agent引导收集必要信息：风险简述、执行人、截止时间
3. 显示预览并请求确认
4. 自动生成task_id（格式：`{employee_no}-{timestamp_ms}-{sequence:3d}`）
5. 下发给指定的Staff成员

#### 任务状态流转图
```
已创建 ──→ 已下发 ──→ 反馈中 ──→ 已完成
           │          │
           └─ 下发失败 └─ 已超时
```

#### 状态说明
| 状态 | 触发条件 | 说明 |
|------|---------|------|
| 已创建 | 创建时 | 任务刚创建，尚未下发给执行人 |
| 已下发 | Manager确认执行人 | 任务已下发给执行人，等待反馈 |
| 反馈中 | 执行人首次回复 | 执行人正在处理，已提交材料或开始对话 |
| 已完成 | 执行人确认 + 材料通过 | 任务完成，反馈总结生成完毕 |
| 已超时 | 自动检测 | 超过feedback_deadline未完成 |
| 下发失败 | 异常发生 | 任务发送/分配失败 |

#### 超时规则
| 任务类型 | 默认超时 | 可自定义 | 说明 |
|---------|---------|---------|------|
| 日度 | 24小时 | 是 | 当日下发，次日下午完成 |
| 月度 | 72小时 | 是 | 月初下发，3天内完成 |

#### 超期处理
- 系统自动检测feedback_deadline是否超时
- 超时时自动更新status为"已超时"
- 可配置定时任务定期检查并推送提醒（规划中）

### 3.4 AI智能体对话

#### Manager Agent（业务负责人工作区）

**核心职责**:
1. **风险数据分析** - 分析风险数据，识别需要核查的风险点，生成分析报告
2. **文件解析** - 支持CSV、Excel、PDF、Word文件上传和内容解析
3. **执行人推荐** - 基于历史数据推荐最合适的执行人
4. **任务创建指导** - 引导创建清晰的任务，提供最佳实践建议
5. **数据查询** - 支持灵活的数据查询和多维分析

**可用工具**（18个MCP工具）:
- **数据查询**: `mcp__djagent_tools__read_risk_data`, `query_data`, `query_risk_data_by_criteria`
- **文件解析**: `parse_csv`, `parse_excel`, `parse_pdf`, `parse_word`
- **用户查询**: `list_users`, `get_user_detail`
- **任务操作**: `create_task`, `assign_task`, `get_task_detail`, `get_task_status`, `update_task_status`
- **数据库操作**: `list_tables`, `describe_table`

**初始对话体验**:
- 欢迎语 + 功能引导
- 快捷功能卡片（5个）：
  - 📊 今日风险分析 - 分析当日高风险
  - 📈 月度重点风险 - 分析本月趋势
  - 📋 任务下发统计 - 统计下发情况
  - ✏️ 创建自定义任务 - 引导任务创建
  - 📁 文件上传分析 - 支持文件解析

**对话示例**:
```
Manager: "帮我分析一下今天的高风险数据"
Agent: [调用read_risk_data工具]
      → 返回分析报告，建议核查的风险点

Manager: "为这个风险创建一个核查任务"
Agent: [调用task_creator Skill]
      → 引导收集执行人、截止时间等信息
      → 调用create_task创建任务
```

#### Staff Agent（一线人员工作区）

**核心职责**:
1. **任务推送** - 通过SSE推送Manager创建的新任务给指定执行人
2. **核查指导** - 告诉一线人员需要提交的材料类型和内容要求
3. **材料审核** - 初步判断上传材料是否符合任务要求
4. **反馈总结生成** - 根据聊天记录和上传材料生成反馈总结
5. **进度督促** - 提醒一线人员在feedback_deadline之前完成反馈
6. **问题解答** - 通过自然对话回答一线人员的疑问

**可用Skills**（6个业务技能）:
- `risk_analyzer` - 风险数据分析和通俗解读
- `task_creator` - 任务创建指导
- `receiver_recommender` - 执行人推荐
- `summary_generator` - 反馈总结生成
- `核查_guider` - 核查指导（中文命名）
- `hello_world` - 演示用Skill

**对话示例**:
```
Agent: "您有一个新任务：运单WLYD001重量异常核查（已超时）"
      [推送通知] 完成期限：2026-03-24 10:00

Staff: "这个任务需要我做什么？"
Agent: [调用核查_guider Skill]
      → 需要提交货物照片、称重凭证、现场检查报告

Staff: [上传3张照片 + 称重凭证]
Agent: [调用summary_generator Skill]
      → 生成反馈总结，提交Manager审核
```

### 3.5 文件管理

#### 上传功能
- 支持拖拽上传和点击上传
- 支持的格式：PDF、JPG、PNG、DOCX、DOC
- 单文件大小限制：< 50MB
- 存储路径：`data/uploads/{task_id}/{filename}`

#### AI文件处理
- **PDF**: 提取文本内容（前3页）+ 表格识别
- **Word**: 提取段落文本 + 表格识别
- **图片**: 显示基本信息 + 内容描述
- **Excel**: CSV转换 + 表格解析

#### 文件索引
所有上传文件信息记录到`data/feedback/{task_id}.json`中：
```json
{
  "uploaded_files": [
    {"filename": "photo_1.jpg", "size": 2048576, "upload_time": "2026-03-21 10:30"},
    {"filename": "report.pdf", "size": 1024000, "upload_time": "2026-03-21 11:00"}
  ]
}
```

### 3.6 实时通知系统（SSE）

#### 推送事件类型
- **task_assigned**: 有新任务分配给用户
- **task_status_changed**: 任务状态发生变化
- **feedback_received**: 一线人员提交了新反馈
- **summary_generated**: AI生成了反馈总结

#### 推送机制
- 前端建立SSE连接：`GET /api/events/{employee_id}`
- 后端发送实时事件：`POST /api/events/{employee_id}`
- 自动重连机制：连接断开后自动重新连接

| 字段 | 说明 | 示例 | 备注 |
|------|------|------|------|

| risk_summary | 风险简述 | 运单WLYD001重量异常 | 任务描述，供一线人员理解 |

| region | 所属地区 | 上海区 | 权限控制，一线人员只看自己地区 |

- `发货地`, `收货地`, `发货网点`, `收货网点`

**人员字段**:
- `揽收人`, `揽收人ID`, `对账人`, `客户名称`, `供应商名称`

**物品字段**:
- `货物类型`, `产品类型`, `重量`, `体积`

- `运费金额`, `结算金额`, `公里数`

**时间字段**:
- `发货时间`, `揽收时间`, `派件时间`, `签收时间`

**状态字段**:
- `运单状态`: 在途/派件/签收/异常等

- `风险等级`: **高** (red) / **中** (yellow) / **低** (green)
