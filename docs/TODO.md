## 问题1：Staff端新任务切换失败 ❌

**现象**：
- Manager给一线人员创建了新任务
- SSE收到`new_task`事件
- 但页面没有切换到新任务，聊天记录还是写在旧任务里

**可能原因**：
- `tasks.find()` 在SSE回调时可能找不到新任务（tasks状态未更新）
- 需要在setSelectedTask之前先刷新tasks列表

**待排查**

## 问题2：Web端聊天记录刷新后消失 ❌

**现象**：
- 每次刷新页面后，聊天记录都消失

**期望**：

## 问题3：Web端缺少新建对话/历史对话功能 ❌

**需求**：
1. 在中间栏（智能体对话区域）增加按钮
2. 点击后弹出菜单，包含：
   - **新建对话**：创建一个全新的对话界面
   - **历史对话**：显示历史对话列表，每条显示：
     - 第一句话的摘要（前几个字）
     - 第一次对话的日期时间
3. 点击历史对话后，加载该对话的聊天记录

**UI方案**：

```
┌─────────────────────────────────────┐
│  🤖 智能体对话            📁 +   │  ← + 按钮点击弹出菜单
├─────────────────────────────────────┤
│                                     │
│  [聊天记录显示区域]                  │
│                                     │
│                                     │
├─────────────────────────────────────┤
│  [输入框...]                    ➤   │
└─────────────────────────────────────┘

点击 + 弹出菜单：
┌────────────────────────┐
│ 🆕 新建对话           │
│ ────────────────────  │
│ 📋 历史对话           │
│   - 3-18 15:30 帮我看...  │
│   - 3-17 10:15 这个数...  │
│   - 3-16 09:00 任务...    │
└────────────────────────┘
```

**技术方案**：
1. 聊天记录持久化：
   - 方案A：存后端（每个用户一个对话历史列表 + 每个对话的聊天记录）
   - 方案B：存localStorage（简单但不支持多设备）

2. 新建对话：
   - 生成新的conversation_id
   - 清空当前聊天记录
   - 开始全新对话

3. 历史对话列表：
   - 显示对话创建时间 + 第一条消息摘要
   - 点击后加载该对话的所有聊天记录
